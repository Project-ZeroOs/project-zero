## 3. Workspace Identity Implementation

`WorkspaceId` is implemented as a 128-bit persistent `DistributedId` in `libzero/src/workspace.rs`.

- **Identity Independence:** `WorkspaceId` is generated by `DistributedIdAllocator` in `workspaced`. It is NOT derived from filesystem inodes, directory paths, PIDs, or `ObjectId`s.
- **Identity Stability:** `WorkspaceId` survives daemon restarts, machine reboots, file moves, and workload terminations.

---

## 5. Membership Graph Implementation

Logical context relationship $\text{MEMBER\_OF}(\text{WorkspaceId}, \text{ObjectId})$ is implemented via `WorkspaceMembershipEdge` in `libzero/src/workspace.rs` and `workspaced/src/main.rs`.

- **Idempotency:** `handle_workspace_add_member` and `handle_workspace_remove_member` operate idempotently. Duplicate edge creation returns success without multiplying entries.
- **Multi-Workspace Support:** An `ObjectId` can belong to multiple workspaces simultaneously.
- **Path Decoupling:** Membership is indexed by `(WorkspaceId, ObjectId)`. Physical file renames and directory moves do not alter membership edges.

---

## 6. Workspace Lifecycle Implementation

The full lifecycle state machine is implemented in `workspaced/src/main.rs`:

$$\text{CREATE} \to \text{INITIALIZE} \to \text{ACTIVE} \rightleftharpoons \text{SUSPENDED} \to \text{ARCHIVED} \to \text{DESTROYED}$$

- `OP_WORKSPACE_CREATE`: Allocates `WorkspaceId`, sets state `Active`, initializes control block.
- `OP_WORKSPACE_OPEN`: Restores `Suspended`/`Archived` workspace to `Active`.
- `OP_WORKSPACE_CLOSE` / `OP_WORKSPACE_SUSPEND`: Transitions state to `Suspended`, quiesces agent execution loops.
- `OP_WORKSPACE_RESUME`: Restores `Suspended` workspace and resumes quiesced agent execution loops.
- `OP_WORKSPACE_ARCHIVE`: Transitions state to `Archived`, unloads agent execution loops.
- `OP_WORKSPACE_DELETE`: Executes destruction teardown.

---

## 7. Workload Integration & System Workload Protection

- `OP_WORKSPACE_ATTACH_WORKLOAD`: Attaches a `WorkloadId` to `associated_workloads`.
- **`WS_SYSTEM_0` Protection:** `WS_SYSTEM_0` (`node_id: 0, local_seq: 0`) is enforced as the administrative System Core Workspace. Non-system workloads attempting to attach to `WS_SYSTEM_0` are rejected with `ZeroError::PermissionDenied`.

---

## 8. Agent Integration & Autonomous Persistence

- `WorkspaceAgentBinding` tracks agent execution states (`Active`, `Quiesced`, `UnboundArchived`).
- `OP_WORKSPACE_ATTACH_AGENT` & `OP_WORKSPACE_DETACH_AGENT` manage active bindings.
- **Independent Agent Persistence:** Upon workspace destruction, agent execution loops terminate and binding state transitions to `UnboundArchived`. Persistent agent memory and goal definitions remain in the system agent pool (`/storage/system/agents/`).

---

## 9. Human Intent DAG Implementation

`IntentNode` (64 bytes) and `IntentDependency` (32 bytes) implement the workspace-owned Human Intent DAG in `libzero/src/workspace.rs`.

- **Acyclicity Verification:** `handle_workspace_intent_add_dep` executes an auxiliary reachability search (`check_intent_reachability`). Self-loops and cyclic dependency attempts are rejected with `ZeroError::InvalidRequest`.
- **Persistence:** Intent nodes and dependencies are serialized into `durable_storage` and re-hydrated on daemon recovery.

---

## 10. Capability Envelope & Security Boundary

- `capability_envelope_handle` stores the workspace capability envelope in `WorkspaceControlBlock`.
- **Teardown Revocation:** Upon `OP_WORKSPACE_DELETE`, `workspaced` invokes `sys_channel_close(capability_envelope_handle)` to immediately revoke capability authority derived from the destroyed workspace.

---

## 11. Boot Recovery & Reconciliation Sequence

On `workspaced` startup (`WorkspaceDaemon::new`):
1. Allocator floor recovered.
2. `load_durable_registry()` loads durable storage buffer.
3. Deserializes `object_registry`, `workspaces`, `membership_edges`, `agent_bindings`, `intent_nodes`, and `intent_deps`.
4. Reconciles membership edges against `object_registry`: live objects set edge `Live`; missing/tombstoned objects set edge `StaleUnresolved`.
5. Re-hydrates valid active/suspended workspaces.
6. Zero IPC self-dependencies required during boot!

---

## 12. `STALE_UNRESOLVED` Handling

When a physical file is unlinked (`OP_OBJECT_UNLINK`), `workspaced` marks the object `Tombstoned` and transitions all referencing `WorkspaceMembershipEdge` records across all workspaces to `MembershipEdgeState::StaleUnresolved`. Edges are NOT deleted.

When the physical object is re-discovered or re-linked via `OP_OBJECT_RECONCILE`, `workspaced` transitions edge state back to `MembershipEdgeState::Live`.

---

## 13. Workspace Destruction Teardown Semantics

`handle_workspace_delete` implements the exact REV1 destruction cascade:
1. `MEMBER_OF` edges for the destroyed workspace are purged. Membership edges of other workspaces remain 100% UNTOUCHED.
2. Physical ZeroFS files remain 100% INTACT.
3. Attached workloads are terminated.
4. Agent bindings transition to `UnboundArchived` (persistent agent memory preserved).
5. Workspace capability envelope handle is closed.
6. Workspace state set to `Destroyed` / `Reclaimed`.

---

## 14. Offline-First Semantics

All workspace identity management, membership queries, intent DAG updates, and reconciliation operations execute 100% locally in `workspaced` without network or remote fabric dependencies.

---

## 15. Persistence & Durability Model

`save_durable_registry()` serializes in-memory tables into `durable_storage` (250 KB buffer) with CRC32 checksums:
- Section 1: Header (64 B)
- Section 2: Object Registry (40,960 B)
- Section 3: Workspaces (32,768 B)
- Section 4: Membership Edges (12,288 B)

`load_durable_registry()` validates CRC32 checksums and deserializes state on startup.

---

## 16. Crash Model & Atomicity Analysis

- Static analysis verifies that manifest updates and membership mutations write atomically to `durable_storage`.
- Incomplete writes or corruption detected via CRC32 checksum mismatch trigger clean fallback during boot recovery.

---

## 17. Concurrency & Synchronization

- Operations within `workspaced` process single-threaded IPC requests from `service_channel` synchronously in main event loop, preventing race conditions on workspace slots and membership arrays.
